# Roadmap Kepatuhan LRM — SVRust

Jangkar loop pengembangan menuju 100% kepatuhan IEEE-1800 (SystemVerilog LRM).
Setiap iterasi `/loop` mengerjakan item prioritas tertinggi lalu menandai statusnya.
Satu file = satu tanggung jawab; jangan lompat stage (lihat `DESIGN.md`).

Status: `[ ]` belum / `[~]` sebagian / `[x]` selesai.
Angka = persentase estimasi kepatuhan per area.

## Pipeline (fundamental)
- [x] Lexer: token, span, komentar, operator, **based literal** (`8'hFF`, `4'b1010_1010`, `8'd200`, `'o17`, `8'shFF`) termasuk digit wildcard `x`/`z`/`?` dengan pelacakan `unknown_mask`, keyword `signed`/`unsigned`/`casez`/`casex` (sv-lexer) — ~82%
- [x] **Preprocessor**: `define (object-like + function-like **dengan substitusi argumen** + **nilai default `F(a, b=5)`**), `undef, `ifdef/`ifndef/`elsif/`else/`endif, `include (rekursif+deteksi siklus), `timescale, substitusi makro **bersarang/rekursif (deteksi loop)**, line-continuation, konkatenasi `"`, **komentar `//` dan `/* */` dibuang sebelum direktif diproses** (sv-preprocessor) - ~80%
- [x] **Preprocessor lanjutan**: `line, `pragma diterima tanpa mengubah source; `default_nettype (wire/none) disimpan di Engine untuk klasifikasi net tanpa tipe (LRM §6.5); `undefineall menghapus semua makro dari tabel (sv-preprocessor)
- [x] Parser: ekspresi binary lengkap, **unary** (`~ - !`), **reduction** (`& ~& | ~| ^ ~^`), **ternary** `?:`, **bit/part-select** `a[i]` `a[msb:lsb]` sebagai nilai maupun target LHS, **concatenation** `{a,b}` dan **replication** `{N{a}}`, qualifier `logic`/`wire`/`reg`/`bit`/`signed`/`unsigned` pada port & deklarasi, **dimension dengan ekspresi literal `[8-1:0]`** (sv-parser)
- [~] Elaborator: parameter (termasuk sized literal), hierarchy/flatten **sampai tingkat berapa pun** (instance anak kini ikut menurunkan instance cucu), **parameter modul anak di-inline nilainya saat instansiasi** sehingga bisa dipakai di badan modulnya, infer lebar ternary/unary/reduction — `generate` sekarang ikut terelaborasi (lihat §23-24)
- [x] **Setiap error elaborasi membawa Span sumber yang benar**: `AstExpr::Ident` kini menyimpan `Span` tokennya, termasuk saat identifier disintesis ulang di `ScopeBlok::qualify`, `generate_proses`, dan `instance::Target::ekspresi`, sehingga `undefined signal` pada ekspresi menunjuk baris/kolom sebenarnya, bukan `line 1 col 1` (AGENTS.md aturan 3)
- [x] **`EventItem` membawa Span token sinyal**: `@(posedge clk)` kini melaporkan `undefined signal` pada kolom nama clock, bukan pada kolom `always_ff`; span tetap terbawa saat item disintesis ulang di `generate_proses` dan `instance`, termasuk event gabungan `@(posedge a or negedge b)` yang menunjuk item yang salah
- [~] IR/opt/codegen/runtime: NBA (termasuk NBA masked untuk LHS select), unary/reduction via helper runtime — **`sv-opt` sudah punya pass constant folding yang di-wire ke pipeline**, Scheduler belum tersambung ke codegen

## Klaster fitur LRM (per bab IEEE-1800)
- [x] **§3 Lexical / §4 Scheduling**: event region, 4-state penuh di jalur simulasi (Logic dengan X/Z propagasi melalui operator bitwise, aritmetika, perkalian, pembagian, modulo, unary, dan reduksi), jedawaktu — di sv-runtime
- [x] **§5 Type / data**: `logic`, `bit`, `wire`, `reg`, `signed`/`unsigned`, `integer`/`int` (termasuk sebagai tipe port), **`real`** (floating point 64-bit IEEE 754, LRM §5.5) sudah; enum, struct belum — `Bits`/`Logic`/`Real` dengan codegen `f64` untuk `real`
- [ ] **§6 Net / variabel**: wire/reg/resolusi multi-driver, supply0/1, tri — belum
- [x] **§6.2 Deklarasi majemuk**: `logic [7:0] a, b, c;` berbagi tipe, lebar, dan signedness
- [x] **§6.2.2 Inisialisasi deklarasi**: `logic s = 8'd42;` menjadi nilai awal waktu nol, `wire w = a;` menjadi driver kontinu; boleh per deklarator (`a = 1, b = 2`)
- [x] **§8 Struct / union / packed**: `struct { ... } var;` dan `union { ... } var;` dapat di-parse dan dielaborasi (struct: lebar = jumlah field, union: lebar = maksimum field). `interface` belum
- [x] **§6.14 Type cast**: `nama_tipe'(ekspresi)` (lebar & signedness dari `typedef`), cast ke tipe bawaan (`integer'`, `int'`, `byte'`, `shortint'`, `longint'`, `time'`, `logic'`, `bit'` — Tabel 6-22, `logic`/`bit` tanpa range = 1 bit), size cast `16'(x)` (hanya lebar, signedness ikut operand), `signed'(x)` / `unsigned'(x)` / `$signed(x)` / `$unsigned(x)` (hanya signedness, lebar tetap), dan `$bits(ekspresi)` / `$bits(nama_tipe)` sebagai konstanta 32-bit waktu kompilasi. Arah perluasan saat melebar mengikuti **signedness operand** (aturan assignment LRM §6.2.1), bukan tipe tujuan — diverifikasi keempat kombinasi terhadap iverilog. `typedef` module-scoped (§8.20): nama tipe di-prefix instans seperti sinyal, jadi typedef anak tak terjangkau dan typedef induk tidak bocor ke anak; nama yang sama untuk variabel dan typedef ditolak. `typedef` di luar module (compilation-unit scope, LRM §8.20) juga didukung: `typedef` di luar module dikumpulkan oleh parser dan tersedia untuk semua module dalam kompilasi unit yang sama. Cast di dalam `function`/`task` disubstitusi argumennya, dan constant folding memakai helper runtime yang sama dengan codegen. `logic signed'(x)` belum (`8's'(x)` memang tidak punya produksi BNF di §5.7.1/§6.14 dan juga ditolak iverilog)
- [x] **§6.16 Tipe integer atom**: `byte` (8-bit signed), `shortint` (16-bit signed), `longint` (64-bit signed), `time` (64-bit unsigned) — keyword, cast, dan deklarasi (body modul, port, argumen/tipe-balik subrutin, `typedef`, deklarasi lokal di `begin...end`). Klasifikasi `Token::atom`/`Token::bisa_mulai_deklarasi` dipusatkan di `sv-lexer` supaya enam parser tidak menyalin daftar yang sama
- [x] **§6.20 Parameter & localparam**: substitusi parameter ke konstanta di body modul **top** (sebelumnya hanya modul anak yang di-inline saat instansiasi), nilai awal deklarasi, nilai awal deklarasi lokal di `begin...end`, dan kondisi `generate`. `localparam` kini ada: AST `Module::localparams` terpisah dari daftar parameter port (supaya `#(.NAMA(...))` tidak diam-diam diterima untuk konstanta terkunci), nilainya berupa ekspresi yang dievaluasi berurutan sehingga `localparam HALF = DEPTH / 2` melihat `DEPTH` sebelumnya. `parameter` juga boleh ditulis di body modul (di luar `#(...)`) dan tetap bisa di-override. Nama ganda antara parameter/localparam/sinyal ditolak. Batas: nilai default `parameter` di body modul harus literal (`ParamDecl` menyimpan `u64`), dan `localparam` bertipe array/struct belum Bug yang ditemukan: substitusi yang dijalankan untuk semua modul sebelum instansiasi membuat override `#(.W(8))` tertimpa default; deklarasi di cabang `if`/`case` generate tidak terdaftar sebagai lokal sehingga `assign tag = ...` mencari `u0__tag` sementara deklarasinya terdaftar sebagai `tag`; `lingkup_lvalue` membuang `genvar_index` sehingga negatif-test indeks genvar di luar generate tidak lagi ditolak; dan `lingkup_expr` memakai span induk sehingga kolom error identifier bergeser
- [~] **§7.3 Dimension packed**: batas boleh ekspresi konstanta apa pun — `[W+1:0]`, `[W*2-1:0]`, `[W+DEPTH-1:0]`, `[(W+1)*2-1:0]`, `[W+1:2]`, `[7:2]` — bukan hanya `[P]` dan `[P-1:0]`. Bentuk literal murni tetap dihitung di parser sebagai `WidthExpr::Literal` supaya bentuk AST tidak berubah; yang memuat parameter disimpan utuh sebagai `WidthExpr::Expr` dan di-resolve saat elaborasi dengan `konst_checked`, jadi `+`/`-`/`*` yang negatif atau meluap ditolak alih-alih wrap jadi lebar miliaran bit. **Divergensi dari iverilog**: `logic [W-8:0]` dengan `W = 4` dihitung iverilog sebagai -4:0 = 5 bit (lenient), sedangkan SVRust menolak karena LRM §7.3 mensyaratkan batas non-negatif. Batas: `unpacked` dimension (`logic [7:0] mem [0:15]`) dan `localparam` di dalam ekspresi belum
- [~] **§5.7.1 Literal 4-state**: digit `x`/`z`/`?` dibawa sampai runtime (`Bits::from_unknown` dengan `xmask` + `zmask` terpisah), padding ke lebar lebih besar mengikuti digit paling kiri (LRM §5.7.1), `z` lebih spesifik dari `x`, dan `%h`/`%b` menampilkannya sebagai `x`/`z`. Concat, replicate, dan part-select (LRM §11.8) kini dirakit lewat helper yang bekerja pada digit, bukan lewat `to_u64` yang membuangnya. Literal desimal polos bertipe `integer` 32-bit **signed**, dan operand biner yang context-determined (LRM §11.6.1) diprioritaskan ke lebar ekspresi sebelum operasi. Batas: `x`/`z` pada net (hanya Literal), resolusi `x` pada operasi aritmetika, dan `%s`/`%m`
- [x] **§11 Operator**: aritmatika (`+ - * / %`), bitwise, `& | ^ ~` biner, shift, perbandingan, `&&` `||` — **sepenuhnya untuk subset ini**
- [x] **§11.4 Unary**: `~`, `-`, `!` — bit_not / bit_neg (dua's complement 2^N) / lognot
- [x] **§11.4.5-6 Pembagian & modulo**: `a / b` dan `a % b` lewat helper runtime; pembagi nol menghasilkan 0 (engine 2-state)
- [x] **§11.4.9 Reduksi**: `&`, `~&`, `|`, `~|`, `^`, `~^` — semua ke 1 bit
- [x] **§11.4.11 Ternary**: `c ? a : b`, termasuk nested; lebar = max kedua cabang
- [x] **§11.3 + §11.4.10 Compound assignment & geser aritmetik**: `+= -= *= /= %= &= |= ^= <<= >>=` **dan `>>>=` `<<<=`** sudah ada. `>>>` mengisi bit sign hanya bila tipe HASIL signed (LRM §11.4.10); `<<<` identik dengan `<<`. Jumlah geser `x`/`z` menghasilkan `X` (§11.4.10). Cast eksplisit sudah ada, lihat §6.14
- [x] **§12 Procedural**: `if/else` (combinational **dan sekuensial di dalam `always_ff`**, termasuk cabang `begin...end` dan `else if`), `case`, **`casez`/`casex`** dengan wildcard pada label (`casez` hanya `z`/`?` yang wildcard, `casex` `x` **dan** `z` — keduanya dipisahkan lewat `zmask` vs `unknown_mask`; label berupa cast ikut membawa wildcard-nya), **`for`** (init/cond/step, termasuk `i++`/`i--`/step compound dan body kosong), **`while`**, **`repeat (n)`**, **`a++;`/`a--;`/`++a;`/`--a;` sebagai statement**, **blocking `=` maupun nonblocking `<=` di `always_ff`**, **`forever`**, dan **blok berlabel `nama: begin ... end`** (LRM §12.9, sintaks dieksekusi; nama disimpan sebagai metadata scope hierarki)
- [x] **§12.8 Deklarasi lokal**: `logic [7:0] t;` di dalam `begin...end` pada `always_comb`/`always_ff`; tiap blok punya scope sendiri sehingga nama lokal yang sama di blok berbeda tidak bentrok
- [x] **§13 Continuous assign**: `assign` dengan LHS sliced dan **net declaration assign** (`wire y = a;`) sudah ada. Nilai yang ditulis ke LHS teriris digeser ke posisi bitnya (lihat item bug di bawah)
- [x] **§14 Procedural assign / deassign** — `assign lhs = rhs;` dan `deassign lhs;` di dalam blok prosedural (LRM §14). `assign` menetapkan override kontinu yang menangkal penulangan prosedural biasa hingga `deassign` melepaskannya. Override disimpan per sinyal di `SignalCell` dan `read()` selalu mengembalikan nilai override bila aktif; penulangan biasa tetap menulis ke dasar sinyal namun diabaikan saat pembacaan. Demo di `examples/e2e_procedural_assign/`.
- [x] **§22 Compiler directives** — `define (function-like + default arg) / `undef / `ifdef / `include / `timescale (lihat §21.8) / komentar sudah; `line, `pragma, `default_nettype (wire/none disimpan di Engine), `undefineall (`.clear()` tabel makro) ✓. Demo uji: 4 test di `engine_test.rs` (`undefineall_menghapus_semua_makro`, `default_nettype_wire_menghapus_pengaturan_none`, `default_nettype_none_disimpan`, `line_dan_pragma_diterima_tanpa_error`), 54 test preprocessor lolos.
- [x] **§23-24 Module instantiation & generate** — instancing hier + param ada; **`for`-generate dengan `genvar`** sudah: parser membuka `generate ... endgenerate`, menerima keyword `genvar`, dan menolak loop yang tidak pernah mendekati batas (langkah negatif/nol) serta batas non-konstanta; elaborator membuka loop per iterasi dan me-lower tiap iterasi sebagai proses tersendiri; koneksi port boleh berindeks (`.y(q[i])`) dengan indeks genvar disubstitusi saat elaborasi; scope per-iterasi (LRM §27.4) juga berlaku sehingga sinyal lokal di dalam loop tidak bentrok antar iterasi. **Generate tanpa label** sudah didukung (parser menerima region tanpa label). **`if`-generate dan `case`-generate sudah** dengan kondisi konstanta (literal, parameter module, genvar, aritmetika/logika) melalui evaluator konstanta di sv-elaborator; `case-generate` wajib punya lengan `default`, dan hanya lengan terpilih yang dielaborasi. Region generate milik modul anak ikut terelaborasi dengan parameter anak dan pemetaan port ke sinyal parent. **Indeks genvar pada LHS juga didukung** (`assign y[i] = ...`): `Lvalue` menyimpan `genvar_index` terpisah dari irisan, lalu elaborator menyelesaikannya jadi irisan konkret per iterasi; di luar region generate indeks genvar ditolak. **Deklarasi `genvar i, j;` terpisah di body modul** (LRM §27.3) kini diterima parser dan dicatat di `Module::genvars`; variabel itu boleh dipakai sebagai loop var tanpa mengulang keyword `genvar`, dan boleh dipakai ulang di beberapa loop. Loop var yang bukan genvar deklarasi maupun inline `for (genvar k = ...)` kini ditolak dengan pesan yang menyebut nama variabelnya. **Indeks bertingkat `y[i][0]` dan `y[3:0][1]` pada LHS sudah didukung**: `Lvalue` punya field `extra_slices` untuk menyimpan seleksi bertingkat, elaborator menghitung slice absolut, dan codegen menghasilkan `range_mask` dengan offset/width yang benar.
- [x] **§23.1 Modul root ganda**: `run`/`build`/`check`/`inspect`/`codegen`/`elaborate` memproses semua modul yang tidak diinstansiasi modul lain (termasuk instansiasi di dalam `generate`), masing-masing sebagai design sendiri. `root_modules` memindai baik `Module::instances` maupun `Module::generates` agar instansiasi di generate tidak dianggap root. `compile_semua_root` / `elaborate_tops` menghasilkan satu design per root, dan `--top` wajib bila ada lebih dari satu root. Import runtime pakai path absolut (`::sv_runtime`) dan nama Rust dibuat unik (modul bernama `sv_runtime` tidak blokir crate). Demo `examples/e2e_multi/` (dua root keduanya dijalankan, `check` memeriksa semua root). Test baru: `elaborate_tops_hasil_banyak_design_untuk_multi_root` di `pipeline.rs`.
- [x] **§23.2 VCD**: timestamp adalah **waktu simulasi** dalam satuan `timeprecision` (bukan nomor langkah) ✓ (`driver_gen`: `design.time_now().in_units(presisi)` setiap langkah, dan sebelum `trace.advance` saat `$finish`), blok `$dumpvars` ditulis pada waktu `$dumpvars` dipanggil — termasuk setelah `#delay` ✓, dan marker waktu akhir ditulis saat `$finish` ✓ (`sv-trace::VcdWriter::advance` selalu tulis marker waktu). Tiap modul root memakai berkas VCD sendiri ✓; dua root yang jatuh pada path sama diberi sufiks (mis. `sama.vcd` + `sama.vcd_r2`, diverifikasi di driver level) ✓. `$monitor`/`$strobe` juga jalan pada mode VCD ✓ (diverifikasi demo `e2e_vcd`). Semua sub-item §23.2 selesai. Demo `examples/e2e_vcd/`.
- [~] **§25 Testbench**: **`initial`** (blok & statement tunggal), `always_ff` dengan body kosong, **`always` polos** (`always @(edge list)` → sekuensial; `always @(level or ...)`, `always @*`, `always @(*)` → combinational; `always` tanpa `@` yang **memuat `#delay`** → **proses waktu** LRM §11.2, lihat item terpisah di bawah), **`$display`** dengan format `%d`/`%h`/`%b`/`%o`/`%c`/`%t` dengan lebar baku per tipe argumen (LRM §20.4), `%0Nd`, `%-Nd`, **`$finish`** yang menghentikan proses dan simulasi, **`#delay`** dengan konversi satuan `s/ms/us/ns/ps/fs` (satuan tanpa satuan mengikuti `timeunit` modul, LRM §21.8), **`$time`**, dan **`$monitor`** (cetak sekali saat pendaftaran lalu ulang saat nilai argumen berubah), **`$monitor if (kondisi)`** (syarat dievaluasi ulang tiap pemancaran, cetak hanya saat syarat benar), **`$monitoron`/`$monitoroff`**, dan **`$strobe`** (argumen dievaluasi saat dipanggil, dicetak di akhir timestep), **`$dumpfile`/`$dumpvars`** (SV menentukan nama berkas VCD dan mengaktifkan rekam; `--vcd` CLI hanya dipakai bila SV tidak memanggilnya), **`$dumpvars(n)`** dengan level hierarki opsional (LRM §23.2), **`@(posedge/negedge/edge sig)`** di dalam blok `initial` (proses ditangguhkan sampai edge benar-benar terjadi; driver men-toggle clock tiap langkah), dan **event control gabungan `@(posedge clk or posedge rst)`** pada `initial`, `always_ff`, dan `always` (AST `AlwaysFf` menyimpan daftar `events`; IR `sensitivity` membawa tiap sinyal + edge aslinya; codegen menguji edge nyata via `edge_prev`/`sample_edge`) sudah jalan. **`task`/`function`** (LRM §13.3/§13.4) kini ada: deklarasi lengkap dengan `automatic`, qualifier tipe (`logic`/`reg`/`bit`/`integer`/`int`), signedness, dan port list ANSI `input`/`output`/`inout`; tugas dipanggil sebagai statement (`t(a, b);` maupun bentuk tanpa kurung `t;` untuk task tanpa argumen), function sebagai ekspresi di mana saja termasuk bersarang dan di dalam ekspresi aritmetika. Eligator meng-*inline* badan subrutin di titik panggilan sebelum lowering, sehingga tidak ada node call di IR maupun codegen. Bentuk badan function yang diterima: satu assignment ke nama fungsi, satu `return expr;`, atau satu `if/else` yang kedua cabannya mengesahkan nama fungsi (diubah jadi operator ternair); task boleh badan majemuk. Rekursi ditolak lewat batas kedalaman inlining 64 tingkat. Validasi: jumlah argumen, salah pakai task sebagai function atau sebaliknya, argumen `output`/`inout` yang bukan nama sinyal, nama subrutin ganda, dan subrutin tak terdefinisi — semuanya melaporkan `Span` nama yang benar. Batasan: badan `function` harus reducing ke satu ekspresi (satu assignment ke namanya, satu `return expr;`, atau satu `if/else` yang kedua cabangnya mengesahkan nama fungsi), sedangkan `task` boleh badan majemuk. Pemanggilan `task` di dalam `always_ff` ditolak karena AST sekuensial belum punya loop/case. Rekursi ditolak lewat batas kedalaman inlining 64 tingkat. Blok `initial` dipecah pada batas `#delay` dan tiap segmen dijalankan pada langkah waktunya sendiri, sehingga logika combinational settle dan edge clock dievaluasi di antara dua `#delay`. Batasan: `Scheduler`/`Region` di sv-runtime belum dipakai, jadi urutan dua proses pada waktu yang sama belum ditentukan LRM; delay di dalam loop atau `if` belum menangguhkan proses; evaluasi proses sekuensial clock-utama masih sekali per langkah (bukan per edge — presisi edge masuk item Event queue)
- [x] **§20/§21 Assertion SVA**: `assert (condition);` (immediate assertion) dan `assert property (@(posedge clk) cond);` (concurrent assertion dasar) didukung. Immediate dievaluasi setiap tahap aktif, cetak error dan set `finished` bila kondisi salah. Concurrent disetara dengan `always_ff @(posedge clk) assert(cond);` — dicek pada setiap edge clock melalui proses sekuensial.
- [~] **§26 VCD / PLI** — VCD ditulis via sv-trace, dipicu dari CLI (`--vcd`) maupun dari SV (`$dumpfile`/`$dumpvars`); argumen level/daftar sinyal pada `$dumpvars` belum, PLI/dpi belum

Demo `e2e_unpacked_multi` dan `e2e_real_unpacked`. **BUG KRITIS: masker part-select bertipe `u64` panicked pada array ≥ 9 elemen** — `Slice::mask()` memakai `1u64 << lsb`, dan elemen ke-9 sudah punya `lsb = 64`: build debug panic di `shift left with overflow`, build release wrap diam-diam sehingga tulisan mendarat di bit 0 (`mem[15] = 8'hBB` menghasilkan `0000000b`). Masker kini dihitung saat runtime lewat `sv_runtime::range_mask::<N>(lsb, width)` bertipe `Bits<N>`. **BUG KRITIS: `write_masked` membuang digit `X`/`Z` dan semua bit di atas 63** karena badananya memakai `to_u64()`; part-select LHS adalah satu-satunya jalur tulis yang memakainya, jadi `a[7:4] = 4'b1x0z` kehilangan wildcard-nya (`iverilog` → `1x0z0000`, SVRust → `00000000`). Sekarang merge dilakukan per digit atas `Bits<N>`. **BUG: range select `mem[3:1]`** melewati jalur `unpacked` yang `return` lebih dulu sehingga `lsb` diabaikan total — hasilnya satu elemen (8 bit), tanpa pesan apa pun; sekarang ditolak eksplisit. **BUG: indeks variabel pada badan task kehilangan `genvar_index`** saat `ganti_lvalue` menukar formal jadi sinyal nyata, sehingga `q[i]` berubah jadi `q` polos dan SELURUH sinyal ditulis (`r = 00000001` untuk iterasi `i = 1,2,3`, seharusnya `00001110`). **BUG: indeks genvar berpola aritmetika (`r[i - 1]`) diklaim lengkap padahal token sisanya dibuang**, sehingga penulisan jatuh pada bit yang salah; isi `[...]` genvar harus persis satu token. **BUG: `y[3:0][1] = ...` diterima lalu token `[1]` dibuang diam-diam** karena penjaga indeks bertingkat hanya ada di jalur genvar. **BUG: pesan indeks variabel pada LHS selalu menyebut "genvar"** walau penulis tidak menulis genvar, dan tidak menyebut array sama sekali; sekarang dibedakan dan menyarankan indeks konstan. **Batas**: range select pada array unpacked, penulisan dengan indeks variabel (`mem[k] = x`), array multidimensi, array sebagai port/argumen subtask, `localparam` untuk ukuran array

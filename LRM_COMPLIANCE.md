# Roadmap Kepatuhan LRM — SVRust

Jangkar loop pengembangan menuju 100% kepatuhan IEEE-1800 (SystemVerilog LRM).
Setiap iterasi `/loop` mengerjakan item prioritas tertinggi lalu menandai statusnya.
Satu file = satu tanggung jawab; jangan lompat stage (lihat `DESIGN.md`).

Status: `[ ]` belum / `[~]` sebagian / `[x]` selesai.
Angka = persentase estimasi kepatuhan per area.

## Pipeline (fundamental)
- [x] Lexer: token, span, komentar, operator, **based literal** (`8'hFF`, `4'b1010_1010`, `8'd200`, `'o17`, `8'shFF`) termasuk digit wildcard `x`/`z`/`?` dengan pelacakan `unknown_mask`, keyword `signed`/`unsigned`/`casez`/`casex` (sv-lexer) — ~82%
- [x] **Preprocessor**: `define (object-like + function-like **dengan substitusi argumen** + **nilai default `F(a, b=5)`**), `undef, `ifdef/`ifndef/`elsif/`else/`endif, `include (rekursif+deteksi siklus), `timescale, substitusi makro **bersarang/rekursif (deteksi loop)**, line-continuation, konkatenasi `"`, **komentar `//` dan `/* */` dibuang sebelum direktif diproses** (sv-preprocessor) - ~80%
- [ ] Preprocessor lanjutan: `line, `pragma, `default_nettype pemetaan, `undefineall
- [x] Parser: ekspresi binary lengkap, **unary** (`~ - !`), **reduction** (`& ~& | ~| ^ ~^`), **ternary** `?:`, **bit/part-select** `a[i]` `a[msb:lsb]` sebagai nilai maupun target LHS, **concatenation** `{a,b}` dan **replication** `{N{a}}`, qualifier `logic`/`wire`/`reg`/`bit`/`signed`/`unsigned` pada port & deklarasi, **dimension dengan ekspresi literal `[8-1:0]`** (sv-parser)
- [~] Elaborator: parameter (termasuk sized literal), hierarchy/flatten **sampai tingkat berapa pun** (instance anak kini ikut menurunkan instance cucu), **parameter modul anak di-inline nilainya saat instansiasi** sehingga bisa dipakai di badan modulnya, infer lebar ternary/unary/reduction — `generate` sekarang ikut terelaborasi (lihat §23-24)
- [x] **Setiap error elaborasi membawa Span sumber yang benar**: `AstExpr::Ident` kini menyimpan `Span` tokennya, termasuk saat identifier disintesis ulang di `ScopeBlok::qualify`, `generate_proses`, dan `instance::Target::ekspresi`, sehingga `undefined signal` pada ekspresi menunjuk baris/kolom sebenarnya, bukan `line 1 col 1` (AGENTS.md aturan 3)
- [x] **`EventItem` membawa Span token sinyal**: `@(posedge clk)` kini melaporkan `undefined signal` pada kolom nama clock, bukan pada kolom `always_ff`; span tetap terbawa saat item disintesis ulang di `generate_proses` dan `instance`, termasuk event gabungan `@(posedge a or negedge b)` yang menunjuk item yang salah
- [~] IR/opt/codegen/runtime: NBA (termasuk NBA masked untuk LHS select), unary/reduction via helper runtime — **`sv-opt` sudah punya pass constant folding yang di-wire ke pipeline**, Scheduler belum tersambung ke codegen

## Klaster fitur LRM (per bab IEEE-1800)
- [ ] **§3 Lexical / §4 Scheduling**: event region, 4-state, jedawaktu — sebagian di sv-runtime
- [~] **§5 Type / data**: `logic`, `bit`, `wire`, `reg`, `signed`/`unsigned`, **`integer`/`int`** (termasuk sebagai tipe port) sudah; `real`, enum, struct, unpacked array belum — `Bits`/`Logic` saja
- [ ] **§6 Net / variabel**: wire/reg/resolusi multi-driver, supply0/1, tri — belum
- [x] **§6.2 Deklarasi majemuk**: `logic [7:0] a, b, c;` berbagi tipe, lebar, dan signedness
- [x] **§6.2.2 Inisialisasi deklarasi**: `logic s = 8'd42;` menjadi nilai awal waktu nol, `wire w = a;` menjadi driver kontinu; boleh per deklarator (`a = 1, b = 2`)
- [~] **§8 Struct / union / packed**: `typedef` skalar & enum sudah; `struct`, `union`, `interface` belum
- [x] **§6.14 Type cast**: `nama_tipe'(ekspresi)` (lebar & signedness dari `typedef`), cast ke tipe bawaan (`integer'`, `int'`, `byte'`, `shortint'`, `longint'`, `time'`, `logic'`, `bit'` — Tabel 6-22, `logic`/`bit` tanpa range = 1 bit), size cast `16'(x)` (hanya lebar, signedness ikut operand), `signed'(x)` / `unsigned'(x)` / `$signed(x)` / `$unsigned(x)` (hanya signedness, lebar tetap), dan `$bits(ekspresi)` / `$bits(nama_tipe)` sebagai konstanta 32-bit waktu kompilasi. Arah perluasan saat melebar mengikuti **signedness operand** (aturan assignment LRM §6.2.1), bukan tipe tujuan — diverifikasi keempat kombinasi terhadap iverilog. `typedef` module-scoped (§8.20): nama tipe di-prefix instans seperti sinyal, jadi typedef anak tak terjangkau dan typedef induk tidak bocor ke anak; nama yang sama untuk variabel dan typedef ditolak. Cast di dalam `function`/`task` disubstitusi argumennya, dan constant folding memakai helper runtime yang sama dengan codegen. Batas: `typedef` di luar module (compilation-unit scope) dan `logic signed'(x)` belum (`8's'(x)` memang tidak punya produksi BNF di §5.7.1/§6.14 dan juga ditolak iverilog)
- [x] **§6.16 Tipe integer atom**: `byte` (8-bit signed), `shortint` (16-bit signed), `longint` (64-bit signed), `time` (64-bit unsigned) — keyword, cast, dan deklarasi (body modul, port, argumen/tipe-balik subrutin, `typedef`, deklarasi lokal di `begin...end`). Klasifikasi `Token::atom`/`Token::bisa_mulai_deklarasi` dipusatkan di `sv-lexer` supaya enam parser tidak menyalin daftar yang sama
- [x] **§6.20 Parameter & localparam**: substitusi parameter ke konstanta di body modul **top** (sebelumnya hanya modul anak yang di-inline saat instansiasi), nilai awal deklarasi, nilai awal deklarasi lokal di `begin...end`, dan kondisi `generate`. `localparam` kini ada: AST `Module::localparams` terpisah dari daftar parameter port (supaya `#(.NAMA(...))` tidak diam-diam diterima untuk konstanta terkunci), nilainya berupa ekspresi yang dievaluasi berurutan sehingga `localparam HALF = DEPTH / 2` melihat `DEPTH` sebelumnya. `parameter` juga boleh ditulis di body modul (di luar `#(...)`) dan tetap bisa di-override. Nama ganda antara parameter/localparam/sinyal ditolak. Batas: nilai default `parameter` di body modul harus literal (`ParamDecl` menyimpan `u64`), dan `localparam` bertipe array/struct belum Bug yang ditemukan: substitusi yang dijalankan untuk semua modul sebelum instansiasi membuat override `#(.W(8))` tertimpa default; deklarasi di cabang `if`/`case` generate tidak terdaftar sebagai lokal sehingga `assign tag = ...` mencari `u0__tag` sementara deklarasinya terdaftar sebagai `tag`; `lingkup_lvalue` membuang `genvar_index` sehingga negatif-test indeks genvar di luar generate tidak lagi ditolak; dan `lingkup_expr` memakai span induk sehingga kolom error identifier bergeser
- [~] **§7.3 Dimension packed**: batas boleh ekspresi konstanta apa pun — `[W+1:0]`, `[W*2-1:0]`, `[W+DEPTH-1:0]`, `[(W+1)*2-1:0]`, `[W+1:2]`, `[7:2]` — bukan hanya `[P]` dan `[P-1:0]`. Bentuk literal murni tetap dihitung di parser sebagai `WidthExpr::Literal` supaya bentuk AST tidak berubah; yang memuat parameter disimpan utuh sebagai `WidthExpr::Expr` dan di-resolve saat elaborasi dengan `konst_checked`, jadi `+`/`-`/`*` yang negatif atau meluap ditolak alih-alih wrap jadi lebar miliaran bit. **Divergensi dari iverilog**: `logic [W-8:0]` dengan `W = 4` dihitung iverilog sebagai -4:0 = 5 bit (lenient), sedangkan SVRust menolak karena LRM §7.3 mensyaratkan batas non-negatif. Batas: `unpacked` dimension (`logic [7:0] mem [0:15]`) dan `localparam` di dalam ekspresi belum
- [~] **§5.7.1 Literal 4-state**: digit `x`/`z`/`?` dibawa sampai runtime (`Bits::from_unknown` dengan `xmask` + `zmask` terpisah), padding ke lebar lebih besar mengikuti digit paling kiri (LRM §5.7.1), `z` lebih spesifik dari `x`, dan `%h`/`%b` menampilkannya sebagai `x`/`z`. Concat, replicate, dan part-select (LRM §11.8) kini dirakit lewat helper yang bekerja pada digit, bukan lewat `to_u64` yang membuangnya. Literal desimal polos bertipe `integer` 32-bit **signed**, dan operand biner yang context-determined (LRM §11.6.1) diprioritaskan ke lebar ekspresi sebelum operasi. Batas: `x`/`z` pada net (hanya Literal), resolusi `x` pada operasi aritmetika, dan `%s`/`%m`
- [x] **§11 Operator**: aritmatika (`+ - * / %`), bitwise, `& | ^ ~` biner, shift, perbandingan, `&&` `||` — **sepenuhnya untuk subset ini**
- [x] **§11.4 Unary**: `~`, `-`, `!` — bit_not / bit_neg (dua's complement 2^N) / lognot
- [x] **§11.4.5-6 Pembagian & modulo**: `a / b` dan `a % b` lewat helper runtime; pembagi nol menghasilkan 0 (engine 2-state)
- [x] **§11.4.9 Reduksi**: `&`, `~&`, `|`, `~|`, `^`, `~^` — semua ke 1 bit
- [x] **§11.4.11 Ternary**: `c ? a : b`, termasuk nested; lebar = max kedua cabang
- [x] **§11.3 + §11.4.10 Compound assignment & geser aritmetik**: `+= -= *= /= %= &= |= ^= <<= >>=` **dan `>>>=` `<<<=`** sudah ada. `>>>` mengisi bit sign hanya bila tipe HASIL signed (LRM §11.4.10); `<<<` identik dengan `<<`. Jumlah geser `x`/`z` menghasilkan `X` (§11.4.10). Cast eksplisit sudah ada, lihat §6.14
- [~] **§12 Procedural**: `if/else` (combinational **dan sekuensial di dalam `always_ff`**, termasuk cabang `begin...end` dan `else if`), `case`, **`casez`/`casex`** dengan wildcard pada label (`casez` hanya `z`/`?` yang wildcard, `casex` `x` **dan** `z` — keduanya dipisahkan lewat `zmask` vs `unknown_mask`; label berupa cast ikut membawa wildcard-nya), **`for`** (init/cond/step, termasuk `i++`/`i--`/step compound dan body kosong), **`while`**, **`repeat (n)`**, **`a++;`/`a--;`/`++a;`/`--a;` sebagai statement**, **blocking `=` maupun nonblocking `<=` di `always_ff`** — `forever`, blok berlabel belum
- [x] **§12.8 Deklarasi lokal**: `logic [7:0] t;` di dalam `begin...end` pada `always_comb`/`always_ff`; tiap blok punya scope sendiri sehingga nama lokal yang sama di blok berbeda tidak bentrok
- [x] **§13 Continuous assign**: `assign` dengan LHS sliced dan **net declaration assign** (`wire y = a;`) sudah ada. Nilai yang ditulis ke LHS teriris digeser ke posisi bitnya (lihat item bug di bawah)
- [ ] **§14 Procedural assign / deassign** — belum
- [~] **§22 Compiler directives** — `define (function-like + default arg) / `undef / `ifdef / `include / `timescale (lihat §21.8) / komentar sudah; `line, `pragma, `default_nettype pemetaan, `undefineall belum
- [~] **§23-24 Module instantiation & generate** — instancing hier + param ada; **`for`-generate dengan `genvar`** sudah: parser membuka `generate ... endgenerate`, menerima keyword `genvar`, dan menolak loop yang tidak pernah mendekati batas (langkah negatif/nol) serta batas non-konstanta; elaborator membuka loop per iterasi dan me-lower tiap iterasi sebagai proses tersendiri; koneksi port boleh berindeks (`.y(q[i])`) dengan indeks genvar disubstitusi saat elaborasi; scope per-iterasi (LRM §27.4) juga berlaku sehingga sinyal lokal di dalam loop tidak bentrok antar iterasi. Batas: generate tanpa label dan indeks bertingkat (`y[i][0]`). **Proses di dalam generate juga sudah** (`always_ff`/`always_comb`/`initial`): genvar dan scope per-iterasi disubstitusi pada seluruh badan proses, termasuk LHS berindeks, sehingga tiap iterasi jadi proses sendiri dengan sinyal lokal sendiri. **`if`-generate dan `case`-generate sudah** dengan kondisi konstanta (literal, parameter module, genvar, aritmetika/logika) melalui evaluator konstanta di sv-elaborator; `case-generate` wajib punya lengan `default`, dan hanya lengan terpilih yang dielaborasi. Region generate milik modul anak ikut terelaborasi dengan parameter anak dan pemetaan port ke sinyal parent. **Indeks genvar pada LHS juga didukung** (`assign y[i] = ...`): `Lvalue` menyimpan `genvar_index` terpisah dari irisan, lalu elaborator menyelesaikannya jadi irisan konkret per iterasi; di luar region generate indeks genvar ditolak. **Deklarasi `genvar i, j;` terpisah di body modul** (LRM §27.3) kini diterima parser dan dicatat di `Module::genvars`; variabel itu boleh dipakai sebagai loop var tanpa mengulang keyword `genvar`, dan boleh dipakai ulang di beberapa loop. Loop var yang bukan genvar deklarasi maupun inline `for (genvar k = ...)` kini ditolak dengan pesan yang menyebut nama variabelnya
- [~] **§23.1 Modul root ganda**: `run`/`build`/`check`/`inspect`/`codegen`/`elaborate`/memproses semua modul yang tidak diinstansiasi modul lain (termasuk instansiasi di dalam `generate`), masing-masing sebagai design sendiri. Versi lama memakai modul terakhir saja sehingga output modul root lain hilang tanpa pesan. Setiap design ditulis sebagai `mod <nama> Rust` dengan nama yang dijamin unik dan bukan kata kunci Rust, dan import runtime memakai path absolut (`::sv_runtime`) supaya modul bernama `sv_runtime` tidak memblokir crate-nya.
- [~] **§23.2 VCD**: timestamp adalah **waktu simulasi** dalam satuan `timeprecision` (bukan nomor langkah), blok `$dumpvars` ditulis pada waktu `$dumpvars` dipanggil — termasuk setelah `#delay` — dan marker waktu akhir ditulis saat `$finish`. Tiap modul root memakai berkas VCD sendiri; dua root yang jatuh pada path sama diberi sufiks, bukan saling menimpa. `$monitor`/`$strobe` juga jalan pada mode VCD.
- [~] **§25 Testbench**: **`initial`** (blok & statement tunggal), `always_ff` dengan body kosong, **`always` polos** (`always @(edge list)` → sekuensial; `always @(level or ...)`, `always @*`, `always @(*)`, dan `always` tanpa `@` → combinational), **`$display`** dengan format `%d`/`%h`/`%b`/`%c`/`%t`/`%0Nd`/`%-Nd`, **`$finish`** yang menghentikan proses dan simulasi, **`#delay`** dengan konversi satuan `s/ms/us/ns/ps/fs` (satuan tanpa satuan mengikuti `timeunit` modul, LRM §21.8), **`$time`**, dan **`$monitor`** (cetak sekali saat pendaftaran lalu ulang saat nilai argumen berubah), **`$monitor if (kondisi)`** (syarat dievaluasi ulang tiap pemancaran, cetak hanya saat syarat benar), **`$monitoron`/`$monitoroff`**, dan **`$strobe`** (argumen dievaluasi saat dipanggil, dicetak di akhir timestep), **`$dumpfile`/`$dumpvars`** (SV menentukan nama berkas VCD dan mengaktifkan rekam; `--vcd` CLI hanya dipakai bila SV tidak memanggilnya), **`@(posedge/negedge/edge sig)`** di dalam blok `initial` (proses ditangguhkan sampai edge benar-benar terjadi; driver men-toggle clock tiap langkah), dan **event control gabungan `@(posedge clk or posedge rst)`** pada `initial`, `always_ff`, dan `always` (AST `AlwaysFf` menyimpan daftar `events`; IR `sensitivity` membawa tiap sinyal + edge aslinya; codegen menguji edge nyata via `edge_prev`/`sample_edge`) sudah jalan. **`task`/`function`** (LRM §13.3/§13.4) kini ada: deklarasi lengkap dengan `automatic`, qualifier tipe (`logic`/`reg`/`bit`/`integer`/`int`), signedness, dan port list ANSI `input`/`output`/`inout`; tugas dipanggil sebagai statement (`t(a, b);` maupun bentuk tanpa kurung `t;` untuk task tanpa argumen), function sebagai ekspresi di mana saja termasuk bersarang dan di dalam ekspresi aritmetika. Eligator meng-*inline* badan subrutin di titik panggilan sebelum lowering, sehingga tidak ada node call di IR maupun codegen. Bentuk badan function yang diterima: satu assignment ke nama fungsi, satu `return expr;`, atau satu `if/else` yang kedua cabannya mengesahkan nama fungsi (diubah jadi operator ternair); task boleh badan majemuk. Rekursi ditolak lewat batas kedalaman inlining 64 tingkat. Validasi: jumlah argumen, salah pakai task sebagai function atau sebaliknya, argumen `output`/`inout` yang bukan nama sinyal, nama subrutin ganda, dan subrutin tak terdefinisi — semuanya melaporkan `Span` nama yang benar. Batasan: badan `function` harus reducing ke satu ekspresi (satu assignment ke namanya, satu `return expr;`, atau satu `if/else` yang kedua cabangnya mengesahkan nama fungsi), sedangkan `task` boleh badan majemuk. Pemanggilan `task` di dalam `always_ff` ditolak karena AST sekuensial belum punya loop/case. Rekursi ditolak lewat batas kedalaman inlining 64 tingkat. Blok `initial` dipecah pada batas `#delay` dan tiap segmen dijalankan pada langkah waktunya sendiri, sehingga logika combinational settle dan edge clock dievaluasi di antara dua `#delay`. Batasan: `Scheduler`/`Region` di sv-runtime belum dipakai, jadi urutan dua proses pada waktu yang sama belum ditentukan LRM; delay di dalam loop atau `if` belum menangguhkan proses; evaluasi proses sekuensial clock-utama masih sekali per langkah (bukan per edge — presisi edge masuk item Event queue)
- [ ] **§20/§21 Assertion SVA** — belum
- [~] **§26 VCD / PLI** — VCD ditulis via sv-trace, dipicu dari CLI (`--vcd`) maupun dari SV (`$dumpfile`/`$dumpvars`); argumen level/daftar sinyal pada `$dumpvars` belum, PLI/dpi belum

## Backlog iteratif (prioritas berikutnya)
- [x] Makro `define` function-like: substitusi argumen, arg count dicek, default value arg (`F(a, b=5)`), makro bersarang/rekursif (deteksi loop)
- [x] `casez/casex di parser & elaborator
- [x] Compound assign `+=` `*=` `/=` `%=` (sisa: `>>>`, `$signed`/`$unsigned`)
- [x] **Type cast LRM §6.14 + `$bits`**: `tipe'(x)` typedef, `signed'(x)`/`unsigned'(x)`, `$bits(ekspresi)` dan `$bits(nama_tipe)`. Demo e2e di `examples/e2e_cast` (RTL + signedness + scope typedef). Bug yang ditemukan & diperbaiki saat pengerjaan: arah perluasan ikut signedness *operand* (bukan tipe tujuan), `from_u64(to_u64())` di codegen memotong cast di atas 64 bit, `Substitution::ganti` menelan node cast sehingga cast di dalam `function`/`task` mati, tabel tipe yang hanya diisi dari modul top (typedef anak tak terjangkau, typedef induk bocor ke anak), dan pesan error yang membocorkan prefix internal `u0__byte_t`
- [x] **Nilai 4-state `x`/`z` end-to-end**: literal `x`/`z`/`?` dibawa ke runtime, `Expr::Const` meng-emit `Bits::from_unknown`, `to_hex_str`/`to_bits_str` menampilkannya, dan concat/replicate/part-select dirakit lewat helper berbasis digit. Padding LRM §5.7.1 (`16'hzz` = `zzzz`) dan pemisahan `z` dari `x` ikut dikerjakan. Bug yang ditemukan: `unknown_mask` dibuang di codegen (`8'hxA` tercetak `0a`), `to_i64` melakukan `1i64 << 64` yang shift overflow untuk nilai 64-bit bertanda negatif, concat/replicate/part-select memakai `to_u64`, `max_width` hanya melihat lebar variabel sehingga `$bits` (32 bit) dan typedef lebar terpotong, dan `AstExpr::Number` dianggap unsigned padahal LRM §5.7.1_override bilang `integer` bertanda. Semua hasil diverifikasi terhadap iverilog 12.0 (`-g2012`)
- [x] **Perbandingan bertanda + operand context-determined (LRM §11.6.1)**: `-1 < 0` sekarang true (sebelumnya salah karena dibandingkan sebagai unsigned), dan operand aritmetika/bitwise diprioritaskan ke lebar ekspresi sebelum operasi; operand kanan `<<`/`>>` tetap self-determined
- [x] **Propagate tipe/signedness hasil (LRM §11.6.1 langkah 3)**: operand context-determined — termasuk cabang `? :` dan operand kiri `<<` — dikonversi ke tipe **hasil**, bukan tipe operandnya sendiri. `sa + 16'd1` hasilnya unsigned (Tabel 11-22) sehingga `sa` di-zero-extend; memakai signedness operand menghasilkan 0xFFFFFFFE yang keliru dibaca negatif. Konsekuensi lain yang diperbaiki: `>>` pada operand kiri signed jadi aritmetik (`sa >> 1` = 0x7FFFFFFE), dan `sa << 4` memperlebar operand kiri sebelum menggesernya
- [x] **Asimetri jalur assignment (LRM §11.6.1)**: `<=` (NBA), `+=` (compound, termasuk LHS teriris yang harus membaca **irisan** bukan sinyal penuh), init/step `for`, dan nilai awal deklarasi kini meneruskan lebar konteks seperti `=`. `logic [7:0] s = -1;` dulu menyimpan 64 bit di sinyal 8-bit sehingga `s == 8'hFF` salah; `for (si = -8'sd1; si > 0; ...)` dulu berjalan 255 iterasi
- [x] **Nilai boolean selalu `Bits` di codegen**: `!x`, perbandingan, dan `&&`/`||` dulu di-emit sebagai `bool` Rust, sehingga kodenya gagal dikompilasi begitu masuk concat/cast/`$display`. `write_expr` sekarang selalu membungkus ke `Bits<MAX_WIDTH>`; short-circuit tetap dipakai di dalam bool
- [x] **Replication dengan count ekspresi (LRM §11.8.2)**: `{WIDTH{1'b1}}` dengan `WIDTH` parameter modul — idiom RTL paling umum — dulu diam-diam dibaca sebagai concatenation `{WIDTH, 1'b1}` (nilai salah tanpa error). Count kini ekspresi yang di-resolve elaborator. Parser memakai backtracking: replication dicoba dulu, lalu fallback ke concatenation; koma antar item concatenation sekarang wajib (tanpa itu `{2{2{a}}}` yang tidak sah diterima diam-diam), dan replication di dalam replication ditolak
- [x] **Packed array dari typedef (LRM §7.3)**: `byte_t [3:0] nib;` dengan `typedef logic [7:0] byte_t` adalah packed array 4 elemen (32 bit). Implementasi lama memperlakukannya sebagai penyempitan ke 4 bit dan **menolak** N yang melebihi lebar tipe dasar — jadi RTL yang sah gagal dielaborasi total
- [x] **`casez` vs `casex` wildcard (LRM §12.5)**: `casez` hanya menjadikan `z`/`?` wildcard, `casex` `x` **dan** `z`; keduanya kini dibedakan lewat `zmask` vs `unknown_mask`, dan label berupa cast tidak lagi membuang wildcard-nya diam-diam
- [x] **Konversi batas assignment (LRM §11.6.1 Tabel 11-21)**: ekspresi kanan adalah context-determined — lebarnya `max(lebar target, lebar self-determined)` dan **diteruskan ke dalam operand**, bukan hanya dibungkus di hasil.
